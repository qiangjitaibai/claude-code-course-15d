Part 1

快速上手与安装

从零开始，5 分钟完成第一次对话

什么是 Claude Code

Claude Code 是一个 AI 助手工具，就像一个随时待命的智能同事。你不需要懂编程——用中文直接跟它聊天就行。

  • 自然语言交互：像和朋友聊天一样简单
  • 智能理解：即使表达不够精确也能给出有用帮助
  • 所见即所得：直接看到处理结果

安装方式

方式一：命令行安装（推荐）

npm install -g @anthropic-ai/claude-code

方式二：IDE 插件

在 VS Code 或 JetBrains 插件市场搜索「Claude Code」安装即可。安装完成后，打开任意项目文件夹，Claude Code 会自动读取项目上下文。

两种使用模式

模式启动方式适用场景
交互式 REPLclaude日常对话、多轮追问
打印模式claude -p "问题"单次快速提问、脚本集成

接入国内大模型

快、省、稳 —— 国内模型配置指南

为什么选国内模型

  • 响应更快：服务器在国内，1-2 秒内回复
  • 成本更低：比海外模型低 30%-50%
  • 中文更好：成语、俗语、文化语境理解更精准
  • 支付方便：支持支付宝、微信支付

主要厂商

智谱 AI（GLM）

代表模型：GLM-4、GLM-3。优势：中文理解能力强，代码生成质量高。

通义千问（Qwen）

代表模型：Qwen Plus、Qwen Max。优势：多模态能力强，支持图像和代码。

DeepSeek

代表模型：DeepSeek V3。优势：成本极低，适合大量批量处理。

配置方式

方案一：LiteLLM 中转

pip install litellm
litellm --model deepseek/deepseek-chat \
  --api_base https://api.deepseek.com/v1

方案二：One API

一站式管理多个模型 Key，可视化界面，支持 DeepSeek、通义千问、智谱、Moonshot 等几乎所有国内模型。

模型选择策略

任务推荐模型理由
文案生成、日常问答GLM-4 / Qwen Plus性价比高
代码开发、复杂分析Claude Sonnet / Qwen Max推理能力强
大量批量处理DeepSeek V3最省成本
💡 黄金法则：80% 日常任务用国内模型，关键决策用最好的模型。

提示词优化技巧

四大要素法 + 高手进阶思路

四大要素法

每次提问尽量包含：

  1. 做什么：具体任务
  2. 用什么：上传或粘贴材料
  3. 给谁看：受众是谁
  4. 什么格式：表格？列表？段落？

多方案输出

实现这个功能，给我三个方案：
1. 最简单的（快速上线）
2. 最稳健的（适合长期维护）
3. 最优雅的（技术含量最高）
每个方案说明优缺点和适用场景

强制约束

重写这段话，必须遵守：
- 不改变原意
- 控制在 200 字以内
- 用主动语态
- 每段不超过 3 句话
- 至少包含一个具体例子

渐进式细化

第一轮：我需要一份市场分析报告的大纲
第二轮：好的，请展开「竞争格局」这个部分
第三轮：把竞争对手的具体数据填进去
第四轮：加上行动建议

不要一次把规范全说完——先框架，再逐层细化。Claude 在每层都能给出更好的结果。

反向思维：让它找漏洞

我写的这段内容，最可能在哪里出问题？
构造 3 个读者可能提出的反对意见

自我审查

你刚才写了什么？为什么这么写？
有没有可以改进的地方？

这个二次审查经常抓到 Claude 自己疏忽的问题。

斜杠命令（Slash Commands）

55+ 内置命令 + 自定义命令参考

概览

Slash command 是你在 Claude 的交互式会话中用来控制行为的快捷方式，主要分为几类：

  • 内置命令：Claude Code 自带，例如 /help、/clear、/model
  • Skills：你自己定义的命令，基于 SKILL.md 文件
  • 插件命令：来自已安装插件的命令
  • MCP prompts：来自 MCP server 的命令

1. 代码质量（命名、结构、复杂度）

- 每条发现包含：位置、问题、建议修复

子代理（Subagents）

专门处理某类任务的独立 AI 助手

概览

Subagents 是专门处理某类任务的独立 AI 助手。它们拥有隔离的上下文、自己的提示词和工具权限，适合把复杂工作拆分给不同角色。

主要好处

  • 上下文隔离：不会污染主会话
  • 角色分工：每个 agent 专注于一件事
  • 适合并行：多个 agent 可以同时工作
  • 便于委派：Claude 自动选择合适的 agent

配置格式

---
name: code-reviewer
description: 审查代码质量和安全问题
tools: Read, Grep, Bash
model: sonnet
---

# Code Reviewer

你是一个资深代码审查员。关注以下方面：
- 代码质量和可维护性
- 安全漏洞
- 性能问题
- 测试覆盖率

位置范围

串联 Subagents

复杂任务里可以让多个 subagent 依次协作：

  1. Code Reviewer → 发现问题
  2. Implementation Agent → 修复问题
  3. Test Engineer → 验证修复

安装

mkdir -p .claude/agents
cp code-reviewer.md .claude/agents/
cp test-engineer.md .claude/agents/
💡 设计原则：单一职责、描述明确、工具权限最小化。审查型 subagent 只读，实现型适度开放写权限。
Part 2

MCP 集成

Model Context Protocol — 连接外部工具和服务

概览

MCP 是 Claude Code 访问外部工具、服务和 API 的标准协议。你可以把 GitHub、数据库、文件系统、聊天系统等都接到 Claude 里。

MCP 架构

Claude Code  ←→  MCP Server  ←→  外部服务
                                    ├── GitHub
                                    ├── 数据库
                                    ├── 文件系统
                                    └── Slack / Jira

安装方式

HTTP 传输（推荐）

# 基本 HTTP 连接
claude mcp add my-server --transport http --url https://server.example.com

# 带认证
claude mcp add my-server --transport http --url https://server.example.com \
  --header "Authorization: Bearer $TOKEN"

Stdio 传输（本地）

# 本地 Node.js server
claude mcp add github -- npx -y @modelcontextprotocol/server-github

# 带环境变量
GITHUB_TOKEN=xxx claude mcp add github -- npx -y @modelcontextprotocol/server-github

MCP 作为 Slash Command

/mcp__github__list_prs
/mcp__github__pr_review 456
/mcp__jira__create_issue "Bug title" high

管理命令

# 添加 MCP server
claude mcp add <name> -- <command>

# 列出所有 servers
claude mcp list

# 查看详情
claude mcp get <name>

# 移除
claude mcp remove <name>

实战示例：GitHub MCP

# 设置
export GITHUB_TOKEN="your_token"
claude mcp add github -- npx -y @modelcontextprotocol/server-github

# 使用
/mcp__github__list_prs        # 列出 PR
/mcp__github__get_issue 42    # 获取 Issue
/mcp__github__create_pr       # 创建 PR

MCP vs Memory 决策矩阵

需求用 Memory用 MCP
长期规则和偏好✅
项目规范✅
实时数据访问✅
外部 API 调用✅
工具操作✅

安全注意事项

  • 只授权必要的工具
  • 优先使用最小权限
  • 不要把 token 写死在仓库里
  • 用环境变量存认证信息
Part 3

Hooks 钩子

事件驱动的自动化机制 — 25 个事件、4 种类型

概览

Hooks 是在 Claude Code 事件发生时自动执行的 shell 命令，用来做格式化、校验、通知、审计等自动化工作。不需要你手动触发。

Hook 类型（4 类、25 个事件）

Tool Hooks

事件触发时机
PreToolUse工具被调用之前
PostToolUse工具被调用之后
PostToolUseFailure工具调用失败后
PermissionRequest请求权限时

Session Hooks

事件触发时机
SessionStart会话开始
SessionEnd会话结束
StopClaude 停止响应
SubagentStart子代理启动
SubagentStop子代理停止

Task Hooks

事件触发时机
UserPromptSubmit用户提交提示词
TaskCompleted任务完成
TaskCreated任务创建

Lifecycle Hooks

事件触发时机
ConfigChange配置变化
FileChanged文件变化
PreCompact压缩前
PostCompact压缩后

配置示例

// ~/.claude/settings.json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Write",
      "hooks": [{
        "type": "command",
        "command": "~/.claude/hooks/format-code.sh"
      }]
    }],
    "PostToolUse": [{
      "matcher": "Write",
      "hooks": [{
        "type": "command",
        "command": "~/.claude/hooks/security-scan.sh"
      }]
    }],
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "~/.claude/hooks/notify-team.sh"
      }]
    }]
  }
}

常见用途

  • format-code.sh - 写入前自动格式化
  • pre-commit.sh - 提交前跑测试
  • security-scan.sh - 做安全扫描
  • log-bash.sh - 记录 bash 命令
  • validate-prompt.sh - 校验输入
  • notify-team.sh - 发通知

安装

mkdir -p ~/.claude/hooks
cp format-code.sh ~/.claude/hooks/
chmod +x ~/.claude/hooks/*.sh
💡 最佳实践：把 hooks 保持短小明确，只做单一职责。先在本地测试，不要在 hook 里放复杂业务逻辑。

Part 3

检查点（Checkpoints）

保存状态、安全试验、随时回退

概览

Checkpoints 可以让你保存对话状态，并在 Claude Code 会话中回退到之前的时间点。无论你是在探索不同方案、修复错误，还是比较多个实现路径，这个能力都非常有用。

核心概念

概念说明
Checkpoint保存消息、文件和上下文的对话快照
Rewind回到之前的 checkpoint，丢弃之后的更改
Branch Point从同一个 checkpoint 出发，探索多个方案

访问方式

  • 键盘快捷键：按两次 Esc（Esc + Esc）
  • Slash Command：/rewind 或 /checkpoint

Rewind 选项

  1. 恢复代码和对话 - 把文件和消息都恢复
  2. 恢复对话 - 只回退消息，保留当前代码
  3. 恢复代码 - 只回退文件修改，保留对话历史
  4. 从这里开始总结 - 把之后的对话压缩成摘要
  5. 算了 - 取消

自动 Checkpoints

  • 每次用户提示都会自动创建 checkpoint
  • 跨会话保留
  • 30 天后自动清理

工作流模式

探索分支策略

1. 初始实现 → Checkpoint A
2. 尝试方案 1 → Checkpoint B
3. 回退到 Checkpoint A
4. 尝试方案 2 → Checkpoint C
5. 比较 B 和 C 的结果
6. 选择最佳方案继续

安全重构模式

1. 当前状态 → Checkpoint（自动）
2. 开始重构
3. 运行测试
4. 测试通过 → 继续
5. 测试失败 → Rewind 并尝试别的方案

使用场景

场景工作流
探索方案保存 → 试 A → Rewind → 试 B → 比较
安全重构保存 → 重构 → 测试 → 失败时 Rewind
A/B 测试保存 → 设计 A → Rewind → 设计 B
错误恢复发现问题 → Rewind 到正常状态
💡 核心价值：Checkpoints 让你敢于试错。"先试再说"和"试错后回退"变得安全，帮你更快找到正确方案。

适合场景

后台任务

长时间任务不阻塞对话——构建、测试、下载、扫描都可以在后台运行。

权限模式（6 种）

模式行为

acceptEdits自动接受文件编辑
plan只读分析，不做修改
auto后台分类器自动决定
dontAsk除危险操作外全部接受
bypassPermissions全部接受（需要特殊参数）
