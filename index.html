Day 1

快速上手：安装到第一句对话

5月12日 周二

什么是 Claude Code

Claude Code 是一个 AI 助手工具，就像一个随时待命的智能同事。你不需要懂编程——用中文直接跟它聊天就行。

它的三个特点：

  • 自然语言交互：像和朋友聊天一样简单
  • 智能理解：即使表达不够精确也能给出有用帮助
  • 所见即所得：直接看到处理结果

    • 安装 Claude Code

    Claude Code 支持 VS Code 和 JetBrains 插件，直接在插件市场搜索「Claude Code」安装即可。也支持终端命令行方式：

    npm install -g @anthropic-ai/claude-code

    安装完成后，打开任意项目文件夹，Claude Code 会自动读取项目上下文。

    热身：第一句对话

    装好后，试试这些开场：

    介绍一下你自己
    帮我写一段产品介绍
    如何提高工作效率

    两种使用模式

    模式适用场景
    聊天窗口日常对话、多轮追问
    输入框 + 回车单次快速提问

    小技巧：Shift+Enter 可以换行输入多行内容；也可以直接粘贴大段文字。

    给 Claude 提供上下文

    模糊表达（不推荐）：帮我写个文案

    具体表达（推荐）：

    请帮我写一段产品描述文案，产品是智能手表，
主要特点包括健康监测、运动追踪、消息提醒，
目标用户是年轻白领，字数在 200 字左右，风格要时尚现代。

    提供的信息越完整，Claude 给出的结果越精准。

    今日任务

    装好 Claude Code，用上面「具体表达」的模板试试——把智能手表换成你实际在做的产品或项目，看看它给出的文案。

Day 2

接入国内大模型：快、省、稳

5月13日 周三

为什么选国内模型

  • 响应更快：服务器在国内，1-2 秒内回复
  • 成本更低：比海外模型低 30%-50%
  • 中文更好：成语、俗语、文化语境理解更精准
  • 支付方便：支持支付宝、微信支付

    • 主要厂商

    智谱 AI（GLM）

    代表模型：GLM-4、GLM-3

    • 优势：中文理解能力强，代码生成质量高
    • 适用：代码开发、文档生成、智能问答

      • 通义千问（Qwen）

      代表模型：Qwen Plus、Qwen Max

      • 优势：多模态能力强，支持图像和代码
      • 适用：代码补全、代码解释、系统设计

        • 配置方式

        方案一：LiteLLM 中转

        pip install litellm
litellm --model deepseek/deepseek-chat \
  --api_base https://api.deepseek.com/v1

        方案二：One API

        一站式管理多个模型 Key，可视化界面，支持 DeepSeek、通义千问、智谱、Moonshot 等几乎所有国内模型。

        模型选择策略

        任务推荐
        文案生成、日常问答GLM-4 / Qwen Plus
        代码开发、复杂分析Claude Sonnet / Qwen Max
        大量批量处理DeepSeek V3（最省成本）

        黄金法则：80% 日常任务用国内模型，关键决策用最好的模型。

        今日任务

        至少配通一个国内模型。推荐从智谱 GLM-4 或通义千问入手——它们都有免费额度，注册即用。

Day 3

入门基础操作：对话、查看、管理

5月14日 周四

输入框操作

基本操作：

  • 输入问题 → Enter 发送
  • Shift+Enter → 多行输入
  • Ctrl+A / Cmd+A → 全选
  • 直接粘贴剪贴板内容

    • 发送后，Claude Code 会显示「正在思考」，然后逐字显示回复。

    查看回复

    Claude 的回复可能包含：

    • 纯文本说明
    • 列表（项目符号或编号）
    • 代码块（特殊格式显示）
    • 表格（结构化数据）

      • 回复较长时直接滚动查看。

      对话历史

      • 最新消息在最下方
      • 向上滚动看之前的对话
      • Claude 会记住上下文，可以引用之前的内容追问

        • 输出格式控制

        用表格对比这两种方案
        只给我改动的代码，不要解释
        用编号列表列出步骤

        格式说清楚，Claude 就不会给你不需要的形式。

        三个核心习惯

        1. 具体再具体：不要说「帮我写个文案」，说「帮我写一段 200 字的智能手表产品描述，目标用户年轻白领，风格时尚」
        2. 一次一个任务：一个问句塞三个需求，Claude 容易顾此失彼
        3. 追问确认：收到结果后追问「为什么这么写？」或「能换个风格吗？」，质量翻倍

        常用命令

        • /clear：清空当前对话，重新开始
        • /compact：压缩对话历史（上下文快满时用）
        • /status：查看当前模型和用量

          • 今日任务

          用 Claude Code 完成一个完整对话：提问 → 看回复 → 追问 → 确认。感受对话历史的上下文记忆能力。

Day 4

文本处理与创作：文案到周报

5月15日 周五

产品描述创作

方法：提供产品名、特点、目标用户、风格。

示例输入：

请帮我写一款智能耳机的产品描述，主要特点包括：
降噪功能、长续航、舒适佩戴、音质出色，
目标用户是年轻白领，风格要时尚现代。

Claude 会生成类似这样的文案：

> 【SoundPro 智能降噪耳机】——你的私人音乐空间

>

> 在喧嚣的城市中，找到一片宁静的音乐天地。SoundPro 采用先进的主动降噪技术，有效隔绝外界噪音……超长续航 30 小时，支持快充……人体工学设计，轻量化机身仅 250g……

广告文案

创意广告示例——智能水杯：

请帮我写一个创意广告文案，产品是智能水杯，
功能包括：提醒喝水、记录饮水量、温度显示，
目标用户是上班族。

促销广告示例——咖啡店周年庆：

咖啡店周年庆，全场买一送一，活动三天。
帮我写促销文案。

邮件写作

有背景的邮件请求：

请帮我写一封邮件，背景是：客户对我们的产品提出了
一个功能需求，我们需要回复客户，告知这个需求
已经记录下来，会考虑在后续版本中实现，同时感谢反馈。

周报和日报

git log --since="last monday" --author="你的名字" --oneline \
  | claude -p "根据 git 提交记录写本周工作总结"

翻译与国际化

把这些中文翻译成英文，保持 JSON 结构不变
检查代码里有没有中文硬编码文本，建议放到 i18n 文件

写作技巧：说清受众和场景

模糊清晰
帮我写个介绍用于公司官网产品页，目标用户是潜在客户，语言专业不晦涩
帮我介绍产品受众是没有技术背景的普通用户，语言通俗易懂，避免专业术语

今日任务

用 Claude Code 帮你写一段你真实需要的文案——产品介绍、周报、邮件都可以。记住说清：产品特点、目标用户、字数、风格。

文档管理与处理：长文提取术

5月18日 周一

从长文档提取关键信息

提取摘要

请帮我为这篇文档生成一个 200 字的摘要
（然后上传文档或粘贴内容）

Claude 会输出类似：

  • 本文档介绍了公司 2026 年度工作计划
  • 总体目标：营收增长 20%，拓展 3 个新市场
  • 市场策略：加强线上营销，优化产品线……

    • 提取要点

    请从这个会议纪要中提取决议事项
（上传会议纪要）

    输出示例：

    1. 产品开发：决定开发移动端 APP，预计 6 个月完成
    2. 市场推广：投入 100 万用于线上广告投放
    3. 团队调整：新增市场部经理岗位，技术团队扩充 5 人

    提取特定信息

    请从这个合同中提取所有的日期信息
（上传合同文件）

    输出：

    • 合同签订日期：2024 年 1 月 15 日
    • 首付款日期：2024 年 2 月 1 日
    • 尾款日期：2025 年 1 月 15 日……

      • 生成详细摘要

      请为这份报告生成详细摘要，包括：
背景、方法、结果、结论

      安全审查代码

      审查这些接口的安全性：
- 哪些接口没有鉴权？
- 有没有 SQL 注入风险？
- 用户输入有没有被校验和清洗？
- 敏感信息有没有泄漏到日志里？

      依赖分析

      分析所有模块的依赖关系，画出依赖图，标出循环依赖
      package.json 里哪些依赖是多余的？哪些有已知安全漏洞？

      今日任务

      找一份你手头的长文档（PDF、会议纪要、合周都可以），让 Claude 提取关键信息。上传或粘贴都行——感受一下它从 5000 字里抓出 5 个要点的能力。

Day 7

个性化工作流：模板和习惯

5月20日 周三

创建常用模板

模板让你不用每次都重复写一样的提示词。

文案生成模板

请帮我写一段[类型]文案，产品是[产品名称]，
主要特点包括[特点1]、[特点2]、[特点3]，
目标用户是[目标用户]，风格要求是[风格]。

要求：
1. 突出核心卖点
2. 语言生动有趣
3. 字数在[字数]左右
4. 包含行动号召

使用时把方括号里的内容替换掉即可。

多模板管理

你可以拥有多套模板：产品描述、广告文案、社交媒体内容、邮件写作……每套模板专注于一类任务。

保存方式：把模板写进 CLAUDE.md（见下文），或者直接保存在一个文本文件里，用的时候复制粘贴。

让 Claude 记住你的偏好：CLAUDE.md

在项目根目录创建 CLAUDE.md：

# CLAUDE.md

## 项目概述
电商后台管理系统，前端 React + TypeScript，后端 Node.js + Prisma。

## 代码风格
- 函数优先于类
- 注释解释"为什么"，不是"是什么"
- 错误不要吞掉，必须向上抛或记录日志

## 快捷指令
- 说"review" → 自动执行代码审查
- 说"fix" → 分析 bug 并给出修复方案

保存常用提示词

把每次成功的提示词记录下来：

  • 什么场景
  • 怎么问的
  • 结果怎么样
  • 有什么可以改进的

    • 积累 10 个你自己的高效提示词，比收藏 100 个别人的模板更有用。

    今日任务

    1. 创建你的第一个提示词模板（产品描述/邮件/周报，选一个你最常用的场景）
    2. 在你的项目里创建 CLAUDE.md，至少包含项目概述和一条快捷指令

提示词优化技巧（上）：清晰表达

5月21日 周四

模糊 vs 清晰：经典对比

给出具体指令

不推荐：

帮我写个文案

推荐：

请帮我写一段产品描述文案，产品是智能手表，
主要特点包括健康监测、运动追踪、消息提醒，
目标用户是年轻白领，字数在 200 字左右，风格时尚现代。

提供完整信息

不推荐：

帮我分析这个数据

推荐：

请帮我分析这份销售数据，包含：
1. 总体统计（总销售额、平均、最高/最低）
2. 按产品分类统计
3. 按地区分类统计
4. 时间趋势分析
5. 数据洞察和改进建议

明确输出格式

不推荐：

帮我整理这些信息

推荐：

请帮我整理这些信息，输出格式为表格，
包含以下列：姓名、部门、职位、入职日期

说明受众和场景

不推荐：

帮我写个介绍

推荐（面向潜在客户）：

请帮我写一个产品介绍，用于公司官网的产品页面，
目标用户是潜在客户，需要突出核心优势，
语言要专业但不晦涩。

推荐（面向普通用户）：

请帮我介绍产品，受众是没有技术背景的普通用户，
语言要通俗易懂，步骤要详细，避免专业术语。

四大要素总结

每次提问尽量包含：

  1. 做什么：具体任务
  2. 用什么：上传或粘贴材料
  3. 给谁看：受众是谁
  4. 什么格式：表格？列表？段落？

今日任务

用「四大要素法」改写一个你之前问过但效果不好的问题。对比两次输出，感受差距。

Day 10

提示词优化技巧（下）：高手思路

5月25日 周一

多方案输出

不要只让 Claude 给一个答案：

实现这个功能，给我三个方案：
1. 最简单的（快速上线）
2. 最稳健的（适合长期维护）
3. 最优雅的（技术含量最高）
每个方案说明优缺点和适用场景

强制约束

给 Claude 戴上紧箍咒，避免它自由发挥过头：

重写这段话，必须遵守：
- 不改变原意
- 控制在 200 字以内
- 用主动语态
- 每段不超过 3 句话
- 至少包含一个具体例子

对比式提问

方案 A：用表格展示数据
方案 B：用图表展示数据

从以下维度对比：可读性、信息密度、制作成本、适用场景
给出推荐和理由

渐进式细化

第一轮：我需要一份市场分析报告的大纲

第二轮：好的，请展开「竞争格局」这个部分

第三轮：把竞争对手的具体数据填进去

第四轮：加上行动建议

不要一次把规范全说完——先框架，再逐层细化。Claude 在每层都能给出更好的结果。

反向思维：让它找漏洞

我写的这段内容，最可能在哪里出问题？
构造 3 个读者可能提出的反对意见
这段逻辑如果被误解，会产生什么后果？
帮我找出所有有歧义的表达

自我审查

你刚才写了什么？为什么这么写？
有没有可以改进的地方？

这个二次审查经常抓到 Claude 自己疏忽的问题。

今日任务

找一个你最近的任务，用「渐进式细化」分三轮完成——先要框架，再细化一个部分，最后加上具体数据。对比一次输出全部的效果。

Day 11

用编程的思维解决问题：拆解大任务

5月26日 周二

什么是编程思维

编程思维就是把复杂问题分解为简单步骤，然后按逻辑顺序执行。你其实经常用到它——只是没意识到。

日常类比：做菜

  1. 分解问题：准备食材 → 处理食材 → 烹饪 → 装盘
  2. 识别模式：每次做菜都遵循类似步骤
  3. 抽象概括：总结出做菜的一般流程
  4. 算法设计：按照食谱的步骤执行

日常类比：旅行

  1. 分解问题：确定目的地 → 查询交通 → 订票 → 打包 → 出发
  2. 识别模式：每次旅行都遵循类似步骤
  3. 抽象概括：总结出旅行的通用流程
  4. 算法设计：按照计划执行

用编程思维让 Claude 帮你

实例：公司销售额连续三个月下降

用 5W1H 拆解：

  • What：销售额下降
  • Why：市场竞争、产品竞争力、营销效果
  • Who：销售团队、市场团队、产品团队
  • When：近三个月
  • Where：全国市场

    • 然后把每个维度分别丢给 Claude：

    分析近三个月的销售数据，分别按产品、地区、渠道统计趋势
    对比我和竞争对手在产品功能上的差距，
列出一个功能对照表

    大任务拆解实战

    我需要做一个「客户满意度调查分析」。
帮我拆成可执行的小任务，按依赖关系排序。

    Claude 会给出：

    1. 设计调查问卷
    2. 收集数据
    3. 清洗数据
    4. 统计分析
    5. 生成报告

    然后逐个推进——不要一口气让它全做完。

    决策前先做检查清单

    在做这个决策之前，帮我分析：
1. 影响范围：哪些部门会受影响？
2. 风险：最坏的后果是什么？
3. 成本：需要多少资源？
4. 替代方案：还有没有其他选项？
5. 回滚方案：如果出问题怎么补救？

    今日任务

    把你手头一个复杂的任务用 5W1H 或「分解问题→识别模式→抽象概括→算法设计」拆开，选其中一个小块让 Claude 先帮你处理。感受「分步做」比「一次全做」的质量差异。

高级功能：工具、Hook、MCP

5月27日 周三

自定义工具

什么是自定义工具

用户根据自己的需求创建的特定功能模块，可以扩展 Claude Code 的能力：

  • 针对性：针对特定需求设计
  • 可复用：可以多次使用
  • 可配置：可以调整参数

    • 如何查找工具

    1. 官方文档
    2. 社区分享
    3. 插件市场
    4. 搜索引擎

    配置示例：数据清洗工具

    需求：需要一个工具来清洗 Excel 数据。

    定义功能：

    • 删除重复行
    • 填充空白单元格
    • 统一日期格式
    • 统一数字格式

      • 创建提示词模板：

      请帮我清洗这个数据：
- 删除重复行
- 填充空白单元格为"无"
- 统一日期格式为 YYYY-MM-DD
- 统一数字格式为保留两位小数

      把这个模板保存下来，命名为「数据清洗工具」，每次需要时调用。

      Hooks：自动化你的工作流

      Hooks 在特定事件发生时自动执行操作：

      事件触发时机
      PreToolUse工具被调用之前
      PostToolUse工具被调用之后
      Stop会话结束时

      示例：文件保存后自动格式化：

      {"hooks": {"PostToolUse": [{"matcher": "Edit|Write",
  "command": "prettier --write"}]}}

      MCP：扩展能力边界

      MCP（Model Context Protocol）让 Claude 能连接外部工具。常用 MCP Server：

      • GitHub：管理 Issues、PRs、仓库
      • 文件系统：安全的文件访问
      • 数据库：只读查询
      • Slack / Jira：消息和工单管理

        • 今日任务

        1. 把你最常用的一个提示词保存为「自定义工具」——用文本文件或 CLAUDE.md 记录即可
        2. 了解一下你工作中还有哪些重复性操作可以让 Claude + 工具自动化

多文件编辑

Claude Code 的强项：同时理解和修改多个文件。

重构一个模块

把 user 模块下所有 API 调用从 axios 改成 fetch，
同时更新类型定义、错误处理和测试

Claude 会自动：扫描文件 → 找到所有 axios 调用 → 逐个替换 → 更新类型 → 更新测试。不需要你逐个文件指挥。

全局重命名

把项目里所有的 user_token 改名为 access_token，
包括：变量名、数据库字段、API 参数、测试数据

批量添加相同功能

给所有接口加上请求日志：
记录请求方法、路径、耗时、状态码

终端命令

Claude Code 不只是读写文件，还可以执行终端命令：

帮我安装 axios

Claude 会执行 npm install axios

跑一下测试，看看有没有失败的

安全控制

有风险的操作 Claude 会先确认。你也可以设置权限规则：

- 允许：npm install, npm test, npm run build
- 需要确认：git push, npm publish
- 禁止：rm -rf, 任何数据库写操作

调试协助

运行项目看看有没有报错？有的话帮我分析原因
这个函数有时候会返回 NaN，帮我排查哪里可能出问题

Day 14

让 Claude 自动解决问题（下）：从单次到批量

5月29日 周五

记录成功的单次任务

每次成功的任务都是资产。记录这些内容：

  1. 任务描述：做了什么
  2. 任务目标：要达到什么效果
  3. 任务步骤：怎么做的
  4. 任务结果：效果怎么样
  5. 经验教训：下次怎么改进

记录示例

任务：生成智能手表产品文案
- 描述：为新产品生成 200 字左右的产品描述
- 步骤：提供产品信息 → 使用提示词模板生成 → 人工审核调整 → 保存
- 结果：成功生成符合要求的文案
- 经验：提示词模板很有效，可以复用

分析任务的重复性

把过去一个月的任务列出来：

  • 哪些任务每周至少出现一次？
  • 哪些任务步骤和格式完全一样，只是数据不同？
  • 哪些任务自己做要 1 小时，Claude 做只要 5 分钟？

    • 重复性分析示例

    任务：生成产品文案
- 频率：每周一次
- 模式：都是产品文案，格式要求相同
- 变化：产品信息不同，但格式不变
- 价值：每次节省 1-2 小时
- 结论：适合批量处理

    设计批量处理方案

    效率对比

    没有模板时：

    • 每次都要详细描述需求
    • 每次都要调整提示词
    • 每次都要审核结果
    • 耗时：每个任务 10-15 分钟

      • 有模板后：

      • 快速检索模板
      • 替换关键信息
      • 生成一致的结果
      • 耗时：每个任务 3-5 分钟
      • 效率提升 60-70%

        • 今日任务

        回顾过去两周你在 Claude Code 里完成的任务，把最常用的 2-3 个写成标准化模板。下次用的时候复制粘贴改几个词就好。

文档化示例：产品文案生成指南

# 产品文案生成指南

## 文案类型
- 产品描述
- 社交媒体内容
- 邮件内容

## 必备要素
- 产品名称
- 主要特点
- 目标用户
- 字数要求

## 写作要求
- 突出核心卖点
- 符合目标用户需求
- 包含行动号召

## 示例
[示例1：智能手表产品描述]
[示例2：有机蔬菜产品介绍]
[示例3：咖啡店促销文案]

把这样的文档放进项目里，Claude 可以直接参考，输出更一致。

效率收益

维度无文档有文档
每次耗时10-15 分钟3-5 分钟
输出一致性波动大高度一致
新人上手需要培训看文档即可

成本控制

/status  → 查看当前用量和费用
/compact → 压缩上下文，节省 token

省钱技巧：

  1. 用 /compact 而不是开新会话
  2. 简单任务用便宜模型（GLM-4/Qwen）
  3. 复杂任务才用贵模型（Claude Sonnet/Opus）
  4. 写清楚约束——越模糊越费 token
